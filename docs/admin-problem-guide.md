# 网站管理员出题指南

> 适用后台：<https://token7.top/admin/problems>
>
> 目标：从零完成一道题的题面、题解、测试数据配置，并发布到用户端题库。

## 一、出题流程总览

1. 使用管理员账号登录，进入「管理后台 → 题目管理」。
2. 下载 ZIP 测试数据模板（推荐）。
3. 点击「新增题目」，填写基本信息、题面、题解和判题配置。
4. 点击「创建题目」，题目会保存为草稿，并自动生成题目编号。
5. 重新打开这道题的编辑页，在「测试数据版本」中上传 ZIP。
6. 等待服务端校验通过，确认当前版本和测试点数量。
7. 回到列表，点击「发布」。
8. 用用户端或测试账号验收题面、样例和判题结果。

---

## 二、进入题目管理

登录管理员账号后，在左侧导航点击「题目管理」。

页面顶部有两个按钮：

- **ZIP 模板**：下载标准的测试数据压缩包模板。
- **新增题目**：打开新建题目的侧边抽屉。

列表中的题目有三种状态：

| 状态 | 含义 |
| --- | --- |
| 已发布 | 用户端题库可见，可以正常提交 |
| 草稿 / 已下架 | 用户端不可见，可继续编辑和上传测试数据 |
| 已归档 | 退出正常题库流程，历史提交保留 |

行操作说明：

- **编辑**：修改题面、题解、判题配置，或上传新的测试数据版本。
- **发布**：把草稿/已下架/已归档的题目重新发布到用户端。
- **下架**：把已发布题目退回草稿状态，用户端立即隐藏。
- **归档**：移出正常管理流程，历史数据保留；需要时可以再次发布。

> 系统没有硬删除题目的入口。写错或不再使用的题目请用「归档」，不要尝试直接删数据库。

---

## 三、准备测试数据 ZIP

测试数据是判题的核心，建议先准备好再创建题目。

### 3.1 推荐目录结构

```text
test-data.zip
├─ sample/
│  ├─ 1.in
│  ├─ 1.out
│  ├─ 2.in
│  └─ 2.out
└─ hidden/
   ├─ 1.in
   ├─ 1.out
   ├─ 2.in
   └─ 2.out
```

- `sample/`：公开样例。用户能在题目详情页看到输入和输出。
- `hidden/`：隐藏测试点。用户看不到输入，也看不到标准输出，只会在提交后得到判题结果。
- 每个编号必须同时存在 `N.in` 和 `N.out`，例如 `1.in` 必须有 `1.out`。
- `sample/` 和 `hidden/` 的编号分别从 1 开始，各自连续，不能跳号。
- 推荐至少提供 1 组公开样例和若干组隐藏测试点。

### 3.2 文件命名规则

只接受这种文件名：

```text
1.in
1.out
2.in
2.out
...
```

要求：

- 编号必须是正整数，从 1 开始，不能写成 `01.in`、`1.txt`、`case1.in`。
- 每个 `.in` 必须有同名 `.out`。
- 不支持符号链接、加密文件、特殊文件。
- 文件不能是 0 字节。
- 文件必须是 **UTF-8 文本**，建议 UTF-8 无 BOM。
- 即使题目没有输入，`.in` 也不能为空，可以放一个换行符。

### 3.3 支持的压缩包布局

推荐使用上面的 `sample/` + `hidden/` 结构。系统也兼容：

- 所有文件直接放在 ZIP 根目录：`1.in`、`1.out`、`2.in`、`2.out`；
- 所有文件放在同一个顶层目录：`data/1.in`、`data/1.out`；
- 顶层目录下再分 `sample/` 和 `hidden/`：`data/sample/1.in`、`data/hidden/1.in`。

**一次上传只能使用一种布局**，不要一部分文件放根目录、另一部分放 `sample/`，否则会报 `mixed_layout`。

> `sample`、`hidden` 目录名必须小写。使用根目录或普通顶层目录布局时，测试点会被当作默认测试点，用户端不会展示公开样例；正式题目建议始终使用 `sample/` + `hidden/` 结构。

### 3.4 资源限制

| 限制项 | 上限 |
| --- | --- |
| 测试点总数（sample + hidden） | 100 个 |
| 单个文件解压后大小 | 8 MB |
| 全部文件解压后总大小 | 64 MB |
| ZIP 压缩包大小 | 32 MB |
| 解压/压缩比 | 不超过 200 倍 |

如果超出限制，先精简测试数据，或把题目拆成多道题。

### 3.5 简单示例

`sample/1.in`：

```text
1 2
```

`sample/1.out`：

```text
3
```

`hidden/1.in`：

```text
100 200
```

`hidden/1.out`：

```text
300
```

最省事的做法：在「题目管理」页面点击「ZIP 模板」，下载后按模板目录替换文件，再重新压缩成 ZIP。

## 四、新增题目

点击「新增题目」后，按以下四块填写。

### 4.1 基本信息

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 题目标题 | 必填 | 最多 200 字，建议简洁明确 |
| 难度 | 必填 | 简单 / 中等 / 困难 |
| 题目编号 | 自动生成 | 创建成功后自动分配，不需要手填 |
| 算法标签 | 选填 | 最多 12 个，单个标签不超过 40 字；可直接输入新标签 |

建议：

- 标题不要带「简单」「困难」等难度词，难度由难度字段表达。
- 标签尽量复用已有标签，方便用户在题库按知识点筛选。
- 标签是用户端「知识点」筛选的来源，不建议写过于宽泛的词。

### 4.2 题面内容

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 题目描述 | 必填 | 每行会渲染成一个段落，最多 100 行 |
| 输入说明 | 必填 | 纯文本，描述输入格式 |
| 输出说明 | 必填 | 纯文本，描述输出格式 |
| 约束条件 | 选填 | 每行一个约束，最多 50 行，例如 `1 ≤ n ≤ 100000` |

注意：

- 题面是纯文本，不支持 Markdown/HTML。
- 题目描述、约束条件、解题步骤都是**按行拆分**的；空行会被忽略。
- 不要把隐藏测试点的输入输出、标准答案写进题面。
- 输入/输出格式要写清楚空格、换行、大小写、精度等要求。

### 4.3 题解配置

默认关闭。打开「提供题解」后需要填写：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 题解标题 | 必填 | 最多 200 字 |
| 思路说明 | 必填 | 核心思路 |
| 解题步骤 | 必填 | 每行一个步骤，最多 30 步 |
| 时间复杂度 | 必填 | 例如 `O(n)` |
| 空间复杂度 | 必填 | 例如 `O(n)` |
| 多语言参考代码 | 至少一种 | 支持 C++ / C / Java / Python3 |

说明：

- 只提交填写了内容的语言代码，空语言不会保存。
- 如果关闭「提供题解」，已保存的题解会对用户隐藏。
- 参考代码建议本地编译/运行通过后再粘贴，避免误导用户。

### 4.4 判题配置

| 字段 | 默认值 | 范围 |
| --- | --- | --- |
| 时间限制 | 1000 ms | 100–30000 ms |
| 内存限制 | 256 MB | 16–1024 MB |

测试点数量和解压大小由测试数据版本自动统计，不能手填。

### 4.5 创建草稿

点击抽屉底部「创建题目」：

- 题目保存为草稿；
- 系统弹出提示，并自动生成题目编号；
- 此时还不能发布，需要先上传测试数据。

---

## 五、上传测试数据

1. 回到「题目管理」列表，找到刚创建的草稿题。
2. 点击「编辑」。
3. 滚动到「测试数据版本」区域。
4. 点击「选择 ZIP 并上传」，选择准备好的 `.zip` 文件。
5. 等待上传和校验完成。

上传成功后：

- 服务端会返回测试点数量和样例数量；
- 新上传的有效版本会自动成为「当前」版本；
- 旧版本会保留在版本列表中，便于追溯；
- 如果新版本校验失败，当前有效版本不会被替换。

版本列表会显示：

- 版本号（v1、v2…）；
- 文件名；
- 状态；
- 测试点数量；
- 解压大小；
- 上传时间。

展开某一行可以看到该版本的校验错误。

> 上传按钮只有在题目已经创建、处于编辑状态时才可用。先保存题目，再上传测试数据。

---

## 六、发布题目

回到「题目管理」列表，找到草稿题，点击「发布」。

发布前必须满足：

- 题目已保存；
- 当前存在一个校验通过的测试数据版本；
- 题目标题、题面、输入/输出说明等必填字段完整。

如果没有有效测试数据，发布会失败并提示：

```text
发布前必须上传并校验通过测试数据
```

发布成功后，题目会立即出现在用户端题库，状态变为「已发布」。

如果要把题目加入学习计划：进入「管理后台 → 学习计划」，编辑对应计划，在「章节与题目」中搜索并添加这道题，然后发布/保存计划。

---

## 七、用户端验收

发布后不要只看后台状态，至少做一次用户端检查：

1. 打开用户端「题库」，搜索题目标题。
2. 进入题目详情，检查题目描述、输入说明、输出说明和约束条件。
3. 确认公开样例可见，隐藏测试数据不可见。
4. 点击「运行样例」，确认样例输入输出正确。
5. 用测试账号提交一份已知正确的代码，确认能 AC。
6. 检查「题解」标签页是否符合预期（如果开启了题解）。
7. 检查难度、标签、通过率等信息是否正常。

建议用专门的测试账号提交，避免管理账号的统计数据被测试提交污染。

---

## 八、修改、下架与归档

### 修改已发布题目

- 直接点「编辑」修改题面、题解、时间/内存限制，点击「保存修改」后立即生效。
- 上传新的测试数据 ZIP 后，新的有效版本会自动成为当前版本；题目继续保持已发布状态。
- 修改前建议先在本地核对题面和测试数据，避免把错误内容直接推给用户。

### 下架

- 点击「下架」，题目回到草稿状态，用户端立即隐藏。
- 历史提交、通过率等数据保留。
- 修复后可再次点击「发布」。

### 归档

- 点击「归档」，题目退出正常题库管理流程。
- 历史提交保留，不会物理删除。
- 需要重新上线时，可以在列表点击「发布」（前提是仍有有效测试数据）。

## 九、常见错误与处理

| 错误提示/代码 | 原因 | 处理方式 |
| --- | --- | --- |
| 发布前必须上传并校验通过测试数据 | 题目没有有效测试数据版本 | 先编辑题目并上传 ZIP |
| `missing_pair` | 某个 `N.in` 缺少对应的 `N.out`，或反过来 | 补齐同名输入/输出文件 |
| `non_contiguous` | 编号不连续，例如只有 1、2、4 | 从 1 开始连续编号，不能跳号 |
| `invalid_filename` | 文件名不是 `N.in` / `N.out` | 改成纯数字编号，例如 `3.in`，不要用 `03.in` |
| `mixed_layout` | ZIP 里同时出现根目录文件和 `sample/hidden` 目录 | 统一成一种布局 |
| `unexpected_file` | ZIP 里有与测试数据无关的文件或目录 | 删除多余文件，只保留测试数据 |
| `empty_file` | 存在 0 字节文件 | 补内容；无输入题目也至少放一个换行 |
| `invalid_utf8` | 文件不是 UTF-8 编码 | 另存为 UTF-8 无 BOM 后重新打包 |
| `too_many_test_cases` | 测试点超过 100 个 | 精简测试点或拆题 |
| `file_too_large` | 单文件解压后超过 8 MB | 缩小输入/输出规模 |
| `total_too_large` | 总解压大小超过 64 MB | 精简数据或拆题 |
| `suspicious_compression_ratio` | 压缩比超过 200 倍 | 避免用极高压缩比的文件，适当拆分 |
| `PROBLEM_ID_EXISTS` | 手填的题目编号已存在 | 让系统自动生成，不要手动指定重复编号 |
| 题目在用户端看不到 | 状态仍是草稿/已下架/已归档 | 在后台点击「发布」 |
| 题解看不到 | 「提供题解」开关关闭 | 打开开关并保存 |
| 测试数据上传按钮不可用 | 题目还没有创建，或正在保存/加载 | 先创建题目并重新打开编辑页 |

## 十、发布前检查清单

- [ ] 标题、难度、标签已填写，标签数量 ≤ 12。
- [ ] 题目描述、输入说明、输出说明完整且无歧义。
- [ ] 约束条件覆盖数据范围。
- [ ] 至少有一组公开样例，且样例输入输出正确。
- [ ] 隐藏测试点覆盖边界、极值、特殊输入等情况。
- [ ] 每个 `.in` 都有同名 `.out`，编号连续。
- [ ] 文件为 UTF-8、非空、没有多余文件。
- [ ] 时间和内存限制适合目标语言。
- [ ] 如果提供题解，至少有一种语言代码能通过。
- [ ] 已用测试账号完成一次样例运行和一次正式提交。
- [ ] 隐藏测试数据没有出现在题面或公开样例中。
